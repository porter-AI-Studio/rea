名詞解釋 (Glossary)

按本書脈絡整理 REA 調查、證據判讀與目標分析所需術語。

閱讀提醒

定義依正文各章的說法整理；章內素材對統計日期、工具數、版本與 Node.js 條件有差異時，本頁並列來源說法，不替讀者選定一項。這些數字是章內所記錄的來源快照，使用前請回到相應章節核對脈絡。前言說明本書的來源與閱讀方式。

REA 與調查流程

Reverse Engineering Anything (REA)逆向工程任何軟體

定義：把不同軟體目標的分析能力接到 Agent 提問流程的工具；它協助調查，不承諾一鍵還原原始碼。

書內脈絡：本書以 REA 指 morluto/rea 專案。可分析目標類型與實際可用能力受安裝版本、提供者及目標條件影響。

實務提示：先界定目標與問題，再核對 Agent 回答引用的來源位置、限制與 Evidence。

章節：第 1 章、第 2 章、第 14 章

Agent智慧體

定義：透過自然語言提問、呼叫工具並整理結果來協助調查的編碼智慧體。

書內脈絡：Agent 的流暢回答不等於可靠結論；本書要求把說法連回工具結果與證據位置。

實務提示：把問題限縮到一項功能，要求列出依據、涵蓋範圍及仍未知的部分。

章節：第 1 章、第 6 章、第 14 章

MCP (Model Context Protocol)模型上下文協定

定義：本書用來描述 REA 將工具能力接入 Agent 的協定介面。

書內脈絡：安裝章將 MCP 註冊到 Agent；比較章討論 REA、GhidraMCP 與 ida-pro-mcp 等路線。工具清單與介面會隨發行版變動。

實務提示：確認實際註冊的套件、工具清單與版本，不以過時的工具數推斷目前能力。

章節：第 1 章、第 4 章、第 12 章

Provider提供者

定義：執行特定分析工作的引擎或能力來源；Evidence 會記錄提供者身分。

書內脈絡：原生檔案可指定 Hopper 或 Ghidra 等 provider；JavaScript 工作流則可直接分析目錄或 ASAR，不必先接原生引擎。

實務提示：保存 provider 名稱與目標身分，跨工具比較時分別保留各自的 Evidence。

章節：第 3 章、第 5 章、第 7 章、第 13 章

Skill工作流程指示

定義：安裝流程中放入 Agent 的工作流程指示，協助它按 REA 的方式使用能力。

書內脈絡：第四章將 skill 與 MCP 註冊分開說明；安裝程式會改動所選 Agent 的設定。

實務提示：檢查安裝計畫中的路徑與動作，理解要加入的指示及設定內容。

章節：第 4 章

證據與判讀

Evidence證據記錄

定義：把分析對象、環境、操作、結果、來源位置、涵蓋範圍與限制連在一起的可查核記錄。

書內脈絡：本書以 Evidence 作為調查帳本。摘要 view 方便閱讀，具體結論仍須回到完整記錄核對。

實務提示：保留原始結果與目標身分；unknown、partial、unsupported 等狀態要原樣呈現。

章節：第 3 章、第 6 章、第 7 章、第 13 章

Observed / Derived / Inferred觀察／推導／推論

定義：三種不同證據關係：工具取得的材料、依明確規則整理的關係，以及需要檢查前提的推測。

書內脈絡：靜態應用圖可推得程式關係；它不能單獨證明某次執行期行為。書中要求將觀察、推導與推論分開。

實務提示：寫結論時標示證據屬於哪一種，並說明它能支持到哪個範圍。

章節：第 3 章、第 6 章、第 7 章

Coverage涵蓋範圍

定義：記錄分析實際檢查到哪些對象或關係，以及哪些部分仍未涵蓋。

書內脈絡：結果為空不代表功能不存在；只有在已檢查範圍內未找到時，才能如此限定描述。

實務提示：同時保存追蹤起點、比對方式、目標版本和限制，避免把缺席當成不存在。

章節：第 3 章、第 6 章、第 7 章、第 13 章

Unknown / Partial / Unsupported未知／部分／不支援

定義：表示資料不足、只完成部分涵蓋或目前能力不支援的結果狀態。

書內脈絡：本書明確指出這些狀態不能彙總成 pass；未知呼叫目標或不完整應用圖也應保留狀態。

實務提示：不要把 unknown 寫成否定結論，也不要因摘要省略細節就推定分析失敗。

章節：第 3 章、第 7 章、第 13 章

Snapshot快照

定義：保存一次分析結果及其工作流、提供者等身分資訊的資料。

書內脈絡：第十三章說明舊快照未必能直接載入新版；應保留舊檔作歷史觀察，使用新路徑重新分析。

實務提示：比較快照前先核對目標位元組與分析條件，不要替舊資料補造當時未記錄的欄位。

章節：第 3 章、第 13 章

Reconstruction Obligation重建義務

定義：將需要重現的行為列成可逐項查驗的工作項目。

書內脈絡：結案需有唯一實作負責人、必要型別、涵蓋案例的 fixture 與可比較的驗證器；矛盾或殘留未知會讓結案維持開放。

實務提示：不要以靜態應用圖或一段偽程式碼代替行為驗證。

章節：第 3 章、第 6 章

原生分析

Analysis Engine分析引擎

定義：REA 用來檢查原生二進位檔、取得函式資料或偽程式碼的底層工具。

書內脈絡：本書章節介紹 Hopper、Ghidra，也提及 IDA；JavaScript 與 Electron 工作流不要求先安裝這些引擎。

實務提示：先確認目標屬於原生檔案及引擎接受的格式，再診斷 provider 是否就緒。

章節：第 5 章、第 8 章、第 13 章

Ghidra HeadlessGhidra 無介面模式

定義：REA 透過命令列啟動 Ghidra、匯入目標並進行自動分析的工作方式。

書內脈絡：首次匯入會建立暫時資料庫；診斷會檢查版本、headless 啟動器、完整 JDK 與主機條件。

實務提示：區分整體 doctor 未就緒與 Ghidra 個別檢查失敗，必要時限定診斷範圍。

章節：第 5 章、第 13 章

JDK (Java Development Kit)Java 開發套件

定義：Ghidra headless 工作流所需的完整 Java 開發套件。

書內脈絡：第五章將缺少完整 JDK 與缺少 headless 啟動器視為不同的安裝問題；需求依實際 Ghidra 安裝宣告核對。

實務提示：以 Ghidra 的版本要求和診斷輸出確認，不要只檢查是否有 Java 執行環境。

章節：第 5 章

Decompilation反編譯

定義：由分析引擎把編譯產物整理成較可讀表示的分析操作。

書內脈絡：產生的偽程式碼是分析器對編譯產物的重建結果，不是原始碼；變數名稱與排版也不能當成作者原始命名證據。

實務提示：對關鍵推論回查組語、位址、位元組與交叉參照。

章節：第 5 章、第 8 章、第 10 章、第 13 章

Pseudocode偽程式碼

定義：分析引擎呈現的、便於閱讀的程式結構重建結果。

書內脈絡：本書案例用偽程式碼找線索，再回頭檢查實際指令與呼叫者；它不能直接證明原始碼或所有執行行為。

實務提示：把偽程式碼當作調查入口，結論需連回來源位置與其他證據。

章節：第 3 章、第 5 章、第 8 章、第 10 章

Analysis Session分析會話

定義：分析工具在已匯入目標上維持並重用的工作狀態。

書內脈絡：第五章指出 Agent 客戶端逾時時需查看工作是否仍在進行及會話恢復方式；第八章對照 CLI 關閉會話與 MCP 查詢重用已開啟會話。

實務提示：先分辨客戶端等待逾時、分析仍在執行與工作本身失敗。

章節：第 5 章、第 8 章

Firmware韌體

定義：本書列為分析目標的封裝檔案，可能包含壓縮資料、檔案系統與多個執行檔。

書內脈絡：第九章以 Binwalk 辨認區段、以 Unblob 解包，再核對子檔案後進行原生分析；區段命中不等於有效分割區。

實務提示：分清原始韌體偏移與解包子檔位址，並核對來源、路徑及雜湊。

章節：第 9 章

JavaScript 與 Electron

Application Graph應用圖

定義：由 JavaScript 工作流整理出的入口點、模組、匯入、路由、程序邊界、IPC 與原生外掛線索。

書內脈絡：它描述指定產物中的靜態關係；動態名稱、混淆或不完整覆蓋可能留下未知，不能等同實際執行紀錄。

實務提示：保留目標雜湊與 Evidence 身分，並以功能追蹤結果核對應用圖中的路徑。

章節：第 7 章、第 10 章

ASARElectron 封裝檔

定義：本書作為 Electron 應用分析輸入之一的封裝檔格式；REA 可對目錄或 ASAR 執行 JavaScript 工作流。

書內脈絡：第七章指出這類靜態分析不需先接 Hopper、Ghidra 或 IDA；分析指定產物不等於觀察應用實際執行。

實務提示：先確認手上的檔案確屬目標版本，並查看應用圖的涵蓋範圍。

章節：第 7 章、第 10 章

IPC (Inter-Process Communication)程序間通訊

定義：Electron 程序間透過通道傳送呼叫、由另一端處理的程式關係。

書內脈絡：Notes 範例沿著 renderer 公開 API、preload 的 invoke 和 main 的 handle，追到寫入 CSV 的處理常式。

實務提示：同時核對傳送端與接收端的通道名稱；靜態配對不能證明某次操作成功。

章節：第 7 章、第 10 章

Renderer / Preload / Main頁面程序／預載程式／主程序

定義：第七章用來描述 Electron 功能跨層路徑的三個程序角色。

書內脈絡：renderer 觸發頁面 API，preload 暴露受控介面並傳送 IPC，main 接收處理並可執行案例中的寫檔工作。

實務提示：沿功能入口逐層追查，不要只憑 renderer 找到的按鈕推定完整行為。

章節：第 7 章、第 10 章

Source Map來源對照映射

定義：提供來源檔案與打包程式碼對應線索的映射資料。

書內脈絡：映射存在不表示原始碼完整，也不保證與正在執行的版本相同。

實務提示：把映射位置當作導覽線索，再回到打包產物與 Evidence 核對。

章節：第 7 章

CDP (Chrome DevTools Protocol)Chrome 開發者工具協定

定義：第七章用來連接既有本機 Electron／Chromium 頁面並取得頁面、框架與資源觀察的端點協定。

書內脈絡：REA 的被動觀察模式依操作者提供的端點和目標 ID 工作，不執行 renderer 程式碼、不點擊或呼叫 IPC。

實務提示：將執行期觀察與靜態應用圖分別記錄，再核對兩者回答的問題是否相同。

章節：第 7 章

環境、版本與責任

Node.js RuntimeNode.js 執行環境

定義：安裝及執行 REA 命令所依賴的 JavaScript 執行環境。

書內脈絡：章內對 Node.js 版本門檻的說法不一致，且有章節指出 main 與 npm 發行版文件可能不同；正文沒有可供統一採用的版本值。

實務提示：依所裝 npm 發行版的文件及實際診斷結果確認需求，勿把任一素材的版本說法當成永久規格。

章節：第 1 章、第 4 章、第 6 章、第 7 章、第 13 章

Versioned Evidence Schema版本化 Evidence 結構

定義：隨 REA 發行版演進的 Evidence 欄位與回傳結構。

書內脈絡：第三章提醒 Evidence 欄位快照不等於永久 schema；第十三章記載 6.1→6.2 將 Evidence 放在 structuredContent 並移除舊 result 包裝。

實務提示：先辨認實際發行版，再按對應文件讀取成功與錯誤結果。

章節：第 3 章、第 13 章

Stars / GitHub Star星數

定義：用來呈現專案關注度的社群統計數字，不等於功能品質或測試結果。

書內脈絡：第二章並列不同日期與口徑：趨勢日報（2026-10-07）寫總數 9,280、當日新增 2,963；CSDN 單日萬星文（2026-10-10）標題稱 1w+ 單日增量；另有 VID-327、VID-332 影片筆記說法。這些是各來源快照，章內不選作官方紀錄。

實務提示：引用星數時一併寫明來源、日期與統計口徑；不要拿快照替代功能驗證。

章節：第 2 章

MCP Tool CountMCP 工具數

定義：特定來源或發行版所列出的 MCP 工具數量。

書內脈絡：第十二章並列實測文章引述安裝指南的 133 個工具與介紹文章的 126 個；第一、二、六、十三章也提醒來源和版本說法不一。數字是素材記錄，不代表目前工具清單。

實務提示：以安裝版本的實際工具清單確認能力，引用舊數字時標明來源。

章節：第 1 章、第 2 章、第 6 章、第 12 章、第 13 章

Ghidra VersionGhidra 版本

定義：Ghidra 分析引擎的發行版識別資訊，會影響安裝相容條件。

書內脈絡：第五章素材並列舊版教學的 12.1.2，以及新版文件所寫 12.1.x、並以 12.1.4 驗證；它們是不同材料中的版本說法。

實務提示：核對實際安裝版本、對應 REA 文件與 JDK 條件，不將範例版本視為固定要求。

章節：第 5 章、第 13 章

Fail-Closed遇不確定即不放行

定義：遇到矛盾、缺漏或權限不足時，不把狀態提升為通過或等價的處理原則。

書內脈絡：第三章說明 readiness 遇到截斷、不穩定、權限不可用或受影響比較缺漏時須 fail-closed；第十四章要求先確認分析授權與資料處理範圍。

實務提示：保留矛盾證據與未知狀態；未取得必要條件時不要宣稱檢查已通過。

章節：第 3 章、第 14 章
