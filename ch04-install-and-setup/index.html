第 4 章 · Part 2：安裝與上手

安裝與設定：npm、skills 與 rea setup

把套件、Agent 連線與工作流程接好，再檢查所需能力。

先分清楚要裝的是什麼

前三章建立了問題、社群評價與證據模型。開始操作前，先把四個層次分清楚：npm 套件 rea-agents 提供 CLI 與 MCP 伺服器；Agent 的 MCP 註冊讓它能找到這個伺服器；skill 是給 Agent 的調查指示；Hopper、Ghidra 或 IDA 則是深入分析原生二進位檔時才需要的引擎。只安裝 skill，不會自動取得 MCP 工具；只裝 CLI，也不代表某個 Agent 的連線已經生效。

官方安裝文件以 Node.js 與 npm 為起點，但不同材料對 Node.js 版本條件的說法不一致，且專案更新很快。準備環境時請以你要使用的 npm 發行版與官方 README 的現行要求為準。來源只認 morluto/rea 與 npm 的 rea-agents；下載前核對套件與倉庫名稱。

從官方設定精靈開始

官方 README 的最短入口是以下命令。執行後先選要設定的 Agent，查看它提出的路徑與變更，再核准套用；npm 對下載套件的詢問與 REA 對設定變更的核准是兩件事。完成訊息若要求重啟 Agent，應在重啟後才測試新的 MCP 工具。

官方設定入口
npx rea-agents setup

設定計畫會列出所選 Agent 的 MCP 註冊、skill 目的地，以及選用 Hopper 時的安裝或連線步驟。官方文件說明：新偵測到的用戶端可供選擇，但預設不會因偵測到就替你新增註冊；既有 REA 註冊可能預選。套用前會檢查原設定，保留無關項目與註解、建立備份並驗證結果。取消或拒絕計畫不會寫入這些設定。Hopper 是另一個選項，另需明確核准。

這個預覽值得逐項讀完。先核對它認出的 Agent 是否就是你要使用的那一個，再看 MCP 註冊要寫入哪個設定檔、skill 會放在哪個目錄，以及是否打算下載額外軟體。特別是電腦上同時裝有多個編碼 Agent 時，「偵測到」只代表有候選設定位置，不代表你想替每個用戶端都開啟 REA。若既有設定損毀或路徑不安全，官方文件說明整個交易會先停止，不會先裝完 Hopper 才報錯。

ℹ️
先看計畫再動手

若要指定用戶端並只取得預覽，官方提供如下 dry-run 範例。它刻意以 skill=false 示範略過 skill；正式設定前，請依自己的需求檢查這個選項。

官方 dry-run 範例
rea setup --client codex --client cursor --skill=false --dry-run

想直接用 CLI，或只安裝 skill

若想在終端機直接呼叫 rea，官方 README 提供全域安裝與說明命令。全域 CLI 仍需依目標補齊相應分析引擎，且不會自動替每個 Agent 建立 MCP 註冊：

官方全域 CLI 範例
npm install --global rea-agents
rea --help

官方也列出只安裝工作流程指示的命令。這適合先把調查方法放進 Agent，但文件明確說明它不會安裝 REA MCP 註冊或原生分析引擎；若工具尚未出現在當前 Agent 會話中，須再檢查該用戶端的註冊與重新連線。

官方 skill-only 範例
npx skills add morluto/rea --skill reverse-engineer-anything

如果已透過設定精靈選了 Agent，預設會一併安裝對應的工作流程；沒有必要再把不同來源、不同版本的指示疊進同一環境。官方文件特別指出，倉庫 main 可能包含 npm 最新發行版尚未發布的功能，而固定存在的 MCP 註冊會鎖定到設定當下使用的套件版本。看到文件上的新工具名稱時，先以正在執行的伺服器實際提供的工具與 schema 為準。

版本更新也要分開處理。全域安裝的 CLI 有自己的更新路徑；使用 npx 的人則由下次呼叫時選用的套件版本決定。即使套件換新，既有 Agent 註冊與 skill 仍可能指向前一版。官方文件要求更新後再審查相應的設定計畫，並重啟受影響的 Agent。若舊 Evidence 或快照被新版拒絕，先查對應的遷移說明，不要把格式不相容誤認為分析目標突然改變。

檢查能力，而非只看一個燈號

全域安裝後可用官方的 doctor 命令看整體診斷。它只讀取環境與設定，不會修改檔案；但整體 healthy 為 false，也可能只是尚未配置某個與本次任務無關的原生引擎。官方安裝文件建議依任務縮小檢查範圍，例如檢查特定用戶端、skill 或 provider。若目標是靜態 JavaScript／Electron，最直接的驗證是對自己的檔案跑一次該分析命令。

官方診斷命令
rea doctor --json
官方靜態分析檢查範例
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

上述絕對路徑是官方文件的範例路徑，執行時要換成實際目標；Windows 範例可寫成 D:/apps/example。若 doctor 顯示 Ghidra、IDA 或 skill 尚未設定，先看你這次任務是否真的需要它；JavaScript 靜態分析不需原生引擎。若 Agent 的設定檔通過檢查、但當前會話還看不到工具，依完成訊息重啟或重新連線，再檢查正在使用的用戶端設定。

排查時可以依層次往回走：命令列是否能啟動、Agent 設定是否指到同一套件、skill 是否安裝在該用戶端會讀取的位置、分析目標需要的 provider 是否可用。這樣可以區分「找不到 MCP 工具」、「有工具但目標類型不支援」與「分析引擎尚未就緒」三種不同問題。若只需要靜態 JavaScript，先完成那條不需原生引擎的路徑，再進入下一章處理原生分析環境。

⚠️
文件與發行版的時間差

截至 2026-10-13，來源對版本號、支援用戶端與 Node.js 門檻並不一致；官方安裝文件也明列 main 與 npm 發行版可能不同。請以官方 README、所裝套件的對應文件及實際診斷結果為準。舊版快照與 Evidence 也可能受遷移變更影響。

到這裡，REA 的套件、Agent 連線與基本診斷已各有檢查方式。下一章再處理需要深入原生二進位檔時，如何選用 Hopper 或 Ghidra，並確認 JDK 與 provider 的環境。
