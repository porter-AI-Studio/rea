第 1 章 · Part 1：認識 REA

什麼是 REA：讓編碼智慧體讀懂軟體

把「這個功能怎麼做？」變成可以追查來源的調查。

從功能疑問出發

你看到一個應用程式的搜尋、匯出或剪貼簿功能，卻拿不到原始碼。一般編碼 Agent 可以依畫面與你的描述寫出相似介面，但它無從知道已發行程式實際走過哪些模組、函式與資料路徑。逆向工程要回答的正是這個落差：從手上的程式產物與可觀察行為，逐步推回功能的實作關係。

REA 是 Reverse Engineer Anything 的縮寫。依 官方 README，它提供命令列介面（CLI）與模型上下文協定（MCP）伺服器，讓人或支援 MCP 的 Agent 使用同一套調查能力。Agent 負責選問題、追問、解釋與撰寫候選實作；REA 負責接到本機檔案與分析工具，回傳可供查核的結果。可取得的資料由目標產物、分析引擎與執行環境決定。

README 的示範提問把目標、問題、證據要求與後續實作放在同一句話裡。Notes 只是範例名稱，操作前仍須辨識自己的調查目標：

README 示範提問
Understand how search works in the Notes app, show me the evidence, and build a
similar feature for my project.

REA 在流程中做哪一段

使用者提出特定功能；Agent 透過 MCP 呼叫 REA，或由人直接在終端機呼叫 CLI；REA 依目標選擇適用的分析能力，回傳程式碼片段、交叉參照與尚未釐清的地方。Agent 根據材料形成說明，必要時繼續查詢。官方把這件事描述為檢查、追蹤、解釋，再由 Agent 撰寫並測試候選實作，並未宣稱一次輸入就能還原原始專案。

MCP 是 Agent 與工具之間的接線方式；CLI 是人在終端機操作的入口。兩者通向同一類工作流程，所以你可以先用 CLI 看結果，再讓 Agent 追問。

初學者最需要問的是：目前看到的是原始檔案中的事實、工具產出的解讀，還是 Agent 根據線索所作的推論？第三章會專門處理這個問題。

把問題拆成可追查的路徑

以搜尋功能為例，第一個問題可以是「哪個介面觸發查詢」，第二個問題是「查詢從哪個模組進入」，第三個問題才是「資料在何處被篩選」。若目標是 Electron 應用，還可能要穿過 renderer、preload 與主程序的邊界。每一段都要找到對應檔案、函式或觀察結果；若其中一段缺少線索，應保留空白並繼續調查。這種拆法能防止 Agent 看見一個相似名稱，就把整條功能路徑一次講完。

ℹ️
分析在本機執行

官方 README 說明 REA 在本機分析目標，沒有代管分析服務；但若把工具結果交給雲端 Agent，模型服務商仍依自己的資料政策處理收到的內容。評估敏感資料時，應分開看這兩段路徑。

不同目標，需要不同的觀察方式

「任何東西」是專案名稱，不表示任何檔案都能得到同樣深度的答案。原生二進位檔的深度分析仰賴 Hopper、Ghidra 或 IDA 等引擎，可能取得偽程式碼、組合語言、字串、符號與交叉參照。JavaScript 或 Electron 產物可先做靜態分析，盤點模組、匯入、來源地圖、路由及 IPC 邊界；這條路不需要原生分析引擎。.NET 元件、網站、APK、韌體與執行時行為另有各自的工具與前提，不能把某一類目標的成功直接推廣到所有目標。

例如官方 README 提供下列命令，對已擷取的 JavaScript／Electron 目錄或 ASAR 進行分析。路徑是原文占位範例，實際操作須換成自己的絕對路徑。JSON 結果是調查材料，仍要檢查其中標示的證據與限制：

官方 JavaScript 靜態分析範例
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

靜態分析只讀取提供的檔案，不會因此觀察到所有執行時分支。反過來，執行時捕捉會啟動或操作目標，作用範圍與權限又不同。追匯入關係、找函式呼叫、確認實際輸出，各自需要不同證據。REA 能協助組織線索，但無法保證恢復原始碼，也不能替代對候選實作的測試。

這也說明為何「反編譯出的程式碼」不能直接等同原始碼。編譯過程可能移除名稱、改寫控制流程，或者把多個來源層級的動作合併。偽程式碼是閱讀機器碼的一種輔助表示，應與組合語言、字串、交互參照及實際行為互相對照。JavaScript 靜態分析雖然比較接近文字原始碼，也會受到壓縮、打包、來源地圖缺失與動態載入影響。工具能縮短找入口的時間，卻無法替代對證據品質的判斷。

讀懂能力，也讀懂邊界

官方案例包含原生程式的計算函式，以及 Electron 應用中從 renderer 經 preload、IPC 到主程序的路徑。案例展示一條可重複檢查的調查方法，並不是對任意軟體都有效的成功率。若目標只給出壓縮後的檔案、缺少符號，或需要特定環境才能重現行為，結論也會相應受限。

⚠️
數字會隨發行版改變

截至 2026-10-13，素材對 MCP 工具數、Node.js 版本與作業系統支援的說法不一。本文不把其中一個數字視為永久規格；安裝與功能判斷請以官方 README、對應發行版文件及實際工具清單為準。

REA 最適合被理解為把逆向工具接進 Agent 調查的工作層：它讓問題更容易提出，也讓答案有機會附上原始線索。下一章先看它為何迅速引發關注，以及社群對便利性、可靠性與界線提出哪些不同評價。
